Verification pass: **2026-09-05**. Re-verify before any adapter reaches production and at least quarterly; several of these APIs changed hosts or versions within the last 12 months.

## Cross-cutting findings

- **String-encoded integers.** Jupiter (atomic amounts), Stripe (decimal fiat/crypto amounts), and Solana RPC (`uiTokenAmount.amount`) all encode money as strings. Helius DAS/Parsed Events encode some amounts as JSON numbers. Adapters must decode with big-integer/decimal types and reject floats.
- **"Accepted" is not "landed".** Jupiter `/execute`, `tx.jup.ag`, Helius Sender, Privy `signAndSendTransaction`, and raw `sendTransaction` all return before finality. Every execution path must persist the signature and reconcile via `getSignatureStatuses` (and `lastValidBlockHeight` expiry) before reporting success or retrying with a new blockhash.
- **Versioned transactions everywhere.** Jupiter builds v0 transactions with address lookup tables; Solana reads need `maxSupportedTransactionVersion: 0`; Privy policies cannot resolve ALT addresses.
- **Idempotency is uneven.** Privy (24 h keys) and Stripe (`Idempotency-Key`, not re-fetched this pass) support keys; Jupiter, Helius, and Anthropic do not. Application-level dedupe is required on those.
- **Hostname drift in the last year.** Jupiter moved `dev.jup.ag` -> `developers.jup.ag` and `lite-api`/`quote-api v6` -> `api.jup.ag`; Anthropic moved `docs.claude.com` -> `platform.claude.com`; Helius moved REST parsing onto `mainnet.helius-rpc.com`. Pin URLs in config, not code, and re-run this verification when a fetch 404s.
